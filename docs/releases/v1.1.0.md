# VRCLT 1.1

VRCLT 1.1 lets your voice and the subtitles use different engines, adds voice
cloning for Soniox, and comes as a folder build that opens several seconds
sooner. Soniox and Gemini also move to their current models.

## Changes

- **Separate subtitle engine:** the Full view has a **Translation engine**
  picker for your speech and a **Subtitle engine** picker for what others say.
  For example, Gemini can translate your voice while Soniox writes
  speaker-labeled subtitles. Each engine needs its own API key and bills
  separately. The Simple view keeps one engine for both.
- **Soniox voice cloning:** in Settings, **Soniox voice** has a **Clone
  voice…** button. Record up to 2 minutes with your microphone or choose an
  audio file (35 MB at most), name the voice, and press **Use this voice**.
  For a recording, the window gives you about a minute of text to read aloud.
  After you save the settings, translated speech uses that voice in every
  target language. The same window lists and deletes the cloned voices of your
  Soniox project. The sample is uploaded to and stored by Soniox; use only
  your own voice or one you have permission to use.
- **Faster start with the folder build:** next to the single executable there
  is now `vrclt-v1.1.0-windows-x64.zip`, the same app as a folder. The single
  executable unpacks itself on every start; the folder does not. On a
  development PC, loading the app took about 0.8 seconds from the folder and
  about 6.9 seconds from the single executable.
- **Soniox `stt-rt-v6`:** speech recognition uses Soniox's current model.
  Settings saved with `stt-rt-v5` switch to it on their own, because Soniox
  removes v5 on December 15, 2026.
- **Lighter Gemini connection:** VRCLT now talks to Gemini's Live API directly
  instead of through Google's SDK, which takes about a second off startup.
  Translation and the glossary behave as before.
- **Gemini Cantonese:** Cantonese, which Gemini's translation model does not
  cover, runs on `gemini-3.8-live` in place of a legacy preview model.
- **Clearer cloned-voice errors:** when a cloned voice was deleted or failed
  processing, VRCLT stops and says so. It used to reconnect without end.

## Installation

Close the old app first, then download one of the two builds. Each has a
`.sha256` checksum next to it.

- `vrclt-v1.1.0-windows-x64.exe` is a single file. Run it; there is nothing to
  install.
- `vrclt-v1.1.0-windows-x64.zip` starts faster. Extract it anywhere and run
  `vrclt\vrclt.exe`. For a later version, extract the new zip over the same
  folder.

Settings carry over from 1.0 in `%LOCALAPPDATA%\vrclt\config.yaml`, whichever
build you use. On first start VRCLT asks once whether to reset its settings;
choose **No** to keep yours. Run the new build once to refresh the path used by
SteamVR auto-start.

## Validation limits

The changes are covered by the regression tests, which run on GitHub's Windows
runner for every change. That runner also builds both downloads. The new Soniox
and Gemini models and the direct Gemini connection were checked against the
live services with recorded test sentences, and translated speech in a cloned
voice ran against the live Soniox service. Creating a voice was tested against
a local stand-in for Soniox's API. The folder build was checked by loading the
whole app from it; a full session from the folder build, two different engines
running live, and Gemini on a headset have not been checked.
